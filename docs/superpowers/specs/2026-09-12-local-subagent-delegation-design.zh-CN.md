# 本地 Subagent 任务委派设计（中文阅读版）

**状态：** 已接受设计；英文版为规范依据

**规范真源：** [2026-09-12-local-subagent-delegation-design.md](2026-09-12-local-subagent-delegation-design.md)

## 通俗结论

新增一个可选的 `delegate_task` 工具。主 Agent 可以把一项独立的代码库阅读任务交给
一个全新的子会话，等待它完成，再把结果作为普通工具结果继续思考。

第一版刻意只允许子 Agent 读文件和列目录。它不能写文件、执行命令、调用 MCP、再次
创建子 Agent，也不会在后台继续运行。这样先解决“让另一个独立上下文帮忙调查”的核心
需求，不提前引入并发写入、嵌套审批和失控后台任务。

## 为什么是真子会话

子 Agent 不是主会话里偷偷多调一次模型。它拥有真正的 Session ID，自己的 Turn、上下文
压缩、工作区指令和审计记录。`session.created` 会记录父 Session、父 Turn、工具 Item 和
Call ID，因此即使进程中断，也能从事件日志证明谁创建了谁。

子会话不复制父聊天历史，只收到这次委派的任务。这样不会把父上下文中的大量内容重复
发送，也不会把父会话压缩规则耦合进第一版。

## 缓存影响

功能默认关闭，关闭时模型请求完全不变。开启后，父 Agent 的工具列表固定增加一个静态
schema；活跃子 Agent 数量、ID 和状态不会每轮改写到系统提示词里。子结果只像普通工具
结果一样追加在末尾，所以不会因动态状态反复破坏可复用前缀。

## 安全与上限

- 任务最多 16 KiB；结果沿用 64 KiB 工具结果上限。
- 默认超时两分钟，取消父任务会取消子任务。
- 委派深度只有一层。
- 子 Agent 只见 `read_file`、`list_dir`。
- 原始 Provider/数据库错误、路径和凭据不会复制进父结果。
- 子 Turn 会出现在父 `tool.execute` 的 trace 下面，但事件日志才是权威关系。

## 本版不做

不做后台队列、并行 roster、继续对话、send/wait/interrupt、模型切换、父历史 fork、
可写子 Agent、ACP 子进程或远程多 Agent。这些都需要独立设计，不能靠多加几个字段假装
已经支持。
