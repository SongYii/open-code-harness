# Judge 元评测 v2：精确计费、留出集校准与跨服务比较

**英文规范来源：** [Judge meta-evaluation v2](2026-09-11-judge-meta-v2-design.md)。若有差异，以英文版为准。

**状态：** 已接受的规范设计

## 通俗说明

v1 和已经产生的 18 次真实结果保持不动。v2 新增 12 道题，先固定分成 6 道
“校准题”和 6 道“留出验证题”，每题仍重复 3 次。不能看完成绩后再换一套更简单的
验证题：策略会提前记住验证集摘要。DeepSeek 与 OpenAI 使用完全相同的验证题，测试
会机械检查题目、标签和顺序没有漂移。

旧价格类型只能表达“每 token 整数微美元”，无法准确表示 DeepSeek 的小数费率。
新类型改为“每一百万 token 多少整数微美元”，把整次调用加总后只向上取整一次。
价格来源、读取日期、采用峰值还是标准价也进入摘要。DeepSeek 用峰值价格，所以结果
是保守上界；OpenAI 用标准同步价格。

校准策略只照实记录真实校准报告达到的边界：最少正确数以及四种错误的最多数量。
它只能检查预先锁定、配置相同、样本数相同的另一份完整报告。通过只说明留出集没有
比校准表现更差，不代表全世界各种任务都达到同样准确率。

两家服务各有冻结配置和价格。它们都复用现有 OpenAI-compatible 适配器，因此解决的
是“第二个真实服务/模型有没有同样表现”，不是“第二种 API 协议适配器”。
